# 分類ヘッド直前におけるドロップアウト (Dropout) の目的と役割

オライリー本第3章（80ページ）の「3.2.5 分類ヘッドの追加」コードにおける、**`x = self.dropout(x)`** の配置目的と役割について解説します。

---

## 1. 結論：過学習 (Overfitting) を防ぎ、未知のデータへの対応力を高めるため

`[CLS]` トークンから抽出したベクトル表現を分類層 `classifier` (`nn.Linear`) に渡す直前にドロップアウトを挟む目的は、**「特定の特徴量への過度な依存（丸暗記・過学習）を防ぎ、モデルの汎化性能を高めるため」** です。

```text
 ［ [CLS] トークンのベクトル (768次元) ］
                       │
                       ▼
 ［ ★ Dropout 層 (10% の確率でランダムに 0 にする) ］
                       │
                       ▼
 ［ 分類層 classifier (nn.Linear) ］ ──> 最終予測スコア
```

---

## 2. なぜ分類直前にドロップアウトが必要なのか？

### 💡 「丸暗記」の防止とアンサンブル効果

もしドロップアウトを入れずに学習させると、分類層 (`nn.Linear`) は「768 次元のうち、例えば 42 番目と 108 番目の数値の組み合わせ」といった **特定の位置の数値だけに過剰に頼った予測（丸暗記）** をしやすくなります。

分類直前にドロップアウトを配置することで、以下のような効果が生まれます：

1. **ノイズへの耐性向上**:
   毎回ランダムにいくつかの数値が消された（0 にされた）不完全なデータから予測させられるため、モデルは一部の情報が欠けていても正しく感情を判定できる頑健さを身につけます。
2. **アンサンブル（手分け）効果**:
   特定の特徴量だけに頼らず、768 次元全体に散らばる様々な情報をバランスよく使って判定するようになります。

---

## 3. 学習時と推論（テスト）時の挙動の違い

PyTorch の `nn.Dropout` は、実行モードによって自動的に挙動が切り替わります。

| モード | 状態 (`model.train()` / `model.eval()`) | ドロップアウトの挙動 |
| :--- | :--- | :--- |
| **学習時** | `model.train()` モード | 設定された確率（例: 10%）で要素を**ランダムに 0 に落とす** |
| **推論・テスト時** | `model.eval()` モード | **ドロップアウトが無効化**され、全 768 次元のデータがそのまま通過する |

そのため、学習時には過学習を防ぎつつ、実際の推論時（テスト時）にはすべての情報を使ってフルパワーで高精度な予測を行うことができます。

---

## 4. まとめ

`x = self.dropout(x)` は、**「分類器が特定の数値パターンを暗記してしまうのを防ぎ、訓練データ以外の新しい文章が入力された時でも正しく分類できるようにするための安全装置（正則化）」** として配置されています。
