# QAタスクにおける「カスタマーレビュー (context)」と「回答 (answers.text)」の違い

> **📄 出典・参考情報**
> * **参考書籍**: 『機械学習エンジニアのためのTransformers』 (オライリー・ジャパン発行, ISBN: 978-4-87311-995-3)  
> * **該当箇所**: 7.1 節「レビューベースの質問応答システムの構築」 (pp.177-178)  
> * **著者**: Lewis Tunstall, Leandro von Werra, Thomas Wolf / 訳: 中山 光樹  

---

## 💡 1. 結論：何が違うのか？

* **カスタマーレビュー (`context`)**: Amazon等に投稿された **長文のレビュー本文全体（全文）**
* **回答 (`answers.text`)**: その長文レビューの中から、**質問の答えとなる箇所だけをピンポイントで切り抜いたフレーズ**

```text
 ［ カスタマーレビュー (context) ］
   「このキーボードは本当に気に入っています。CAPS LOCKキーがないので星4つにしました。
    私の手はとても大きいですが、★このキーボードはコンパクト★で、何も不満はありません。」
                                │
                                ▼ (質問: 「キーボードはコンパクトですか？」)
                                │  答えとなる箇所を蛍光ペンでハイライトして切り出す！
                                ▼

 ［ 回答 (answers.text) ］: 「このキーボードはコンパクト」
 ［ 開始位置 (answers.answer_start) ］: 215 文字目からスタート
```

---

## 📊 2. 178ページ掲載サンプルデータの各列の役割

| 列名 | 役割 | 178ページ サンプル例 (791行目) |
| :--- | :--- | :--- |
| **`question`** | 質問文 | `"Does the keyboard lightweight?"`<br>(キーボードは軽い/コンパクト？) |
| **`context`** | 投稿されたレビュー本文全体 | `"I really like this keyboard. ... I have very large hands and **this keyboard is compact**, but I have no complaints."` |
| **`answers.text`** | 本文から抜き出した回答 | `["this keyboard is compact"]`<br>(ピンポイントの答えフレーズ) |
| **`answers.answer_start`** | 本文内のスタート位置 | `[215]`<br>(レビュー全文の215文字目から始まる) |

---

## 🔍 3. `answers.text: []` (空リスト) の意味

オライリー本 178 ページのサンプル（1159行目）を見ると、`answers.text` が **`[]`**（空）になっています。

* **`question`**: `"How is the battery?"` (バッテリーはどう？)
* **`context`**: GoProバッテリーについての長文レビュー
* **`answers.text`**: **`[]`** (空)

これは、**「レビュー本文をどれだけ探しても、質問に対する答えが書かれていなかった（回答不能な質問）」** という状態を表しています。

抽出型 QA モデルは、「答えを抜き出す」だけでなく、「本文中に答えがない場合は回答不能（空）と判定する」能力も合わせて学習します。

## 📝 まとめ

* **`context` (レビュー)** ＝ **「長文の教科書ページ全体」**
* **`answers.text` (回答)** ＝ **「教科書の中で蛍光ペン（マーカー）を引いたピンポイントの答え」**
