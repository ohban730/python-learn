# 質問応答 (Question Answering / QA) タスクの全体像と種類

オライリー本第7章（173ページ〜）で扱う **質問応答 (Question Answering)** というタスクがどのようなものであり、実務でどう使われているのかを解きほぐして解説します。

---

## 1. 結論：ごイメージの通りですが、実務・第7章では「根拠文書から答えを探す」スタイルが主流です！

「人間が質問した際、モデルが知識を使って答える」というイメージは**まさに大正解**です。

ただし、NLP（自然言語処理）や第7章の文脈では、質問応答タスクは大きく以下の **2 つのスタイル（＋現代のハイブリッド型 1 つ）** に分類されます。

```text
 ［ スタイル 1: 抽出型/読解型 QA ］ ★第7章のメイン！
   【入力】 質問 ＋ 根拠となる本文（Web記事やマニュアル）
   【動作】 本文の中から「答えとなる単語・フレーズ」をハイライトして抜き出す

 ［ スタイル 2: 閉鎖型 (Closed-book) QA ］ ★ご質問いただいたイメージ！
   【入力】 質問のみ
   【動作】 モデルが事前学習で記憶した知識だけを頼りに回答を生成する

 ［ スタイル 3: 検索拡張型 (RAG: Retrieval-Augmented Generation) ］ ★現代の実務の主流！
   【動作】 検索エンジンで根拠文書を自動検索 ──> その文書を添えてLLMに答えさせる
```

---

## 2. 第7章で扱う「抽出型/読解型 QA (Extractive QA)」とは？

画像（173ページ図7-1）の **Google 検索の例** が最もわかりやすい実例です。

Google で `「キュリー夫人が初めてノーベル賞を受賞したのはいつですか？」` と検索した時、Google は以下の 2 ステップを行っています。

1. **関連文書の検索**: Wikipedia などの Web ページ（テキスト本文）を見つけてくる。
2. **回答スニペットの抽出 (QAタスク)**: その本文の中から `「1903年」` という**答えの場所（開始位置と終了位置）をピンポイントで特定して画面トップにドカンと表示**する。

このように、**「質問」と「回答が含まれる文章（コンテキスト）」の両方をモデルに入力し、文章の中から答えを抜き出すタスク** を **読解型/抽出型 QA** と呼びます。

---

## 3. 2 つのスタイルのメリット・デメリット比較

| 項目 | 抽出型 QA (第7章のメイン) | 閉鎖型 QA (LLM単体での回答) |
| :--- | :--- | :--- |
| **情報のソース** | 外部の本文（コンテキスト） | LLMの内部パラメータ（記憶） |
| **ハルシネーション (嘘)** | **ほぼゼロ**（本文から抜き出すため） | 発生するリスクがある（知識の曖昧さ） |
| **最新情報への対応** | 本文を差し替えるだけで**即対応可能** | 再学習（ファインチューニング）が必要 |
| **主な用途** | **社内ドキュメント検索、FAQ自動応答** | 雑談、アイディア出し、一般的な知識対話 |

---

## 4. 現代のビジネス（RAG）への繋がり

現在大流行している **RAG (検索拡張生成)** システムは、この第7章の考え方がベースになっています。

```text
 ［ ユーザーの質問 ］: 「会社の経費申請の締め切りはいつ？」
         │
         ▼ (社内データべースから関連規定ファイルを検索)
 ［ 根拠マニュアル本文 ］: 「経費申請は毎月25日必着とする...」
         │
         ▼ (質問 ＋ 根拠本文をセットでAIへ入力)
 ［ 質問応答 (QA) ］: 「毎月25日です (根拠: 経費規定第3条)」
```

社内規約や最新マニュアルなどの「モデルが事前学習で知るはずもない社内データ」に対して、**嘘をつかずに正確に回答させるシステムを作るために、この第7章の質問応答（QA）の技術が必須**になります。
