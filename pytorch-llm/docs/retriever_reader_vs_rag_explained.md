# Retriever-Reader アーキテクチャと RAG (検索拡張生成) の違いと関係性

> **📄 出典・参考情報**
> * **参考書籍**: 『機械学習エンジニアのためのTransformers』 (オライリー・ジャパン発行, ISBN: 978-4-87311-995-3)  
> * **該当箇所**: 第7章「質問応答」 7.1節 〜 7.3節 (pp.190-205)  
> * **著者**: Lewis Tunstall, Leandro von Werra, Thomas Wolf / 訳: 中山 光樹  

---

## 💡 1. 結論：思想は同じですが、「回答の作り方」が違います！

`Retriever-Reader` アーキテクチャと `RAG (Retrieval-Augmented Generation)` はほぼ兄弟（歴史的な発展形）の関係にありますが、最大のちがいは **「検索した後の Reader (回答役) が、本文からそのまま切り抜くか、文章を新しく生成するか」** です。

```text
 ［ 1. 伝統的な Retriever-Reader (第7章前半) ］
   検索 (Retriever) ──> 本文から答えをそのまま「切り抜く」 (抽出型 Reader / Extractive)
   ・出力例 : "waterproof at 30m" (本文そのままのコピペ)

 ［ 2. 現代の RAG (Retrieval-Augmented Generation / 第7章後半) ］
   検索 (Retriever) ──> 検索した本文を元に「自然な文章を生成する」 (生成型 LLM / Generative)
   ・出力例 : 「はい、この時計は水深30mまでの防水性能を備えています。」 (自然な対話文)
```

---

## 📊 2. 詳細比較表

| 比較項目 | 抽出型 Retriever-Reader | 現代の RAG (検索拡張生成) |
| :--- | :--- | :--- |
| **Retriever (検索役)** | 検索する (同じ) | 検索する (同じ) |
| **Reader (回答役)** | **抽出型モデル** (XLM-RoBERTa, MiniLM 等) | **生成型 LLM** (Gemini, GPT-4, LLaMA 等) |
| **回答の作成方法** | 本文の中から答えとなる単語を**そのままハイライト/切抜** | 検索された本文を文脈として読み込み、**自然な日本語文を合成** |
| **ハルシネーション** | **ゼロ**（本文のコピペのため） | わずかに発生するリスクあり（言い換えの過程で） |
| **計算コスト / 速度** | **超軽量・超高速・安価** | LLMを使うため比較的高コスト・低速 |
| **主な用途** | ファクトチェック、精度重視の社内ドキュメント検索 | カスタマーサポートチャットボット、要約対話Bot |

---

## 📜 3. 歴史的な進化の流れ

1. **第1世代: 抽出型 Retriever-Reader (オライリー本 7.1〜7.2 節)**
   * 「嘘を絶対につかない」「動作が爆速」「安価」という理由で、社内FAQ検索や事実確認システムとして発展。
2. **第2世代: 現代の RAG (オライリー本 7.3 節〜)**
   * ChatGPT や Gemini 等の巨大LLMの登場により、検索した文章をLLMに読ませて「丁寧にわかりやすい対話形式で答えさせる（Generation）」形へ進化。

---

## 📝 まとめ

* **Retriever-Reader**: RAG の「先祖・基礎構造」にあたる概念。
* **第7章前半のモデル**: 本文から答えを切り抜く **「抽出型 RAG」**。
* **ChatGPTなどのRAG**: 本文を元に自然な会話文を作る **「生成型 RAG」**。
