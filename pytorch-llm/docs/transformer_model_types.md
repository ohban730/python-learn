# Transformer アーキテクチャの 3 タイプ分類 (BERT / GPT / T5)

書籍の63ページに登場する Transformer モデルの 3 つのタイプ（エンコーダのみ / デコーダのみ / エンコーダ・デコーダ）の分類と、**BERT がどこに属するのか**について解説します。

---

## 1. 結論：BERT は「エンコーダのみ」タイプです

BERT（および DistilBERT, RoBERTa など）は、**「エンコーダのみ (Encoder-only)」** のアーキテクチャに分類されます。

デコーダ部分（文章を1文字ずつ生成していく仕組み）を持っておらず、入力された文章全体をじっくり読み込んで高精度な「意味表現（隠れ状態）」を作ることに特化しています。

---

## 2. Transformer の 3 タイプ比較表

| タイプ | 代表的なモデル | アテンションの特徴 | 主な得意タスク |
| :--- | :--- | :--- | :--- |
| **エンコーダのみ** | **BERT**, DistilBERT, RoBERTa | **双方向アテンション**<br>(前後両方の文脈を同時参照) | テキスト分類、感情分析、固有表現抽出、検索 |
| **デコーダのみ** | **GPT-4**, ChatGPT, LLaMA, Claude | **因果的 (Causal) アテンション**<br>(左側の過去文脈のみ参照) | 文章自動生成、対話（チャット）、コード生成 |
| **エンコーダ・デコーダ** | **T5**, BART | 入力は双方向 ＋ 出力は因果的 | 機械翻訳（日英など）、文章要約 |

---

## 3. なぜ BERT は「エンコーダのみ」なのか？

### ① 「双方向アテンション (Bidirectional Attention)」が使えるから
文章生成（GPT等）では「未来の単語をカンニングしてはいけない」ため、左側の単語しか見られません（因果的アテンション）。

一方、BERT などの「エンコーダのみ」モデルは文章を生成するのではなく理解することが目的のため、**入力文章の前後のすべての単語（左右両方）を同時に見渡す** ことができます。

```text
 ［ 入力文 ］: 「私は  [MASK]  に行ってお寿司を食べた。」

  ・デコーダ (GPT): 「私は」までしか見られないため、後ろの「お寿司」の情報を使えない。
  ・エンコーダ (BERT): 前の「私は」と後ろの「お寿司」の両方を同時に見て「築地」や「寿司屋」だと高精度に理解できる！
```

### ② 分類・理解タスクに最適だから
第2章で扱った感情分類のように、**「入力された文章全体を深く理解してラベルを予測する」** タスクにおいては、デコーダによる一文字ずつの生成処理は不要であり、エンコーダの強力な意味抽出機能だけで十分かつ最高の精度が出せます。
