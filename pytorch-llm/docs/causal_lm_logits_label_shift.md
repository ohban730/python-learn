# 因果的言語モデル (Causal LM) におけるロジットとラベルの位置ズレ (Shift) 解説

オライリー本第5章（139ページ）で解説されている **「ロジットとラベルの対応付け」「最後のロジットと最初のラベルを捨てる理由」** についてスッキリ解きほぐして解説します。

---

## 1. 該当の文章

> 「なお、入力系列の対数確率はモデルによって生成されないため、無視します。また、ロジットとラベルを対応させることが重要です。というのも、モデルは次のトークンを予測するので、最初のラベルのロジットは得られず、最後のロジットはそれに対する正解トークンがないので必要ないからです。」

---

## 2. 結論：何を行っているのか？

この文章は、**「言語モデル（GPTなど）は常に『次の1文字』を予測するため、予測出力（ロジット）と正解ラベルの間で 1 文字のズレ（Shift）が生じる。そのため、両端の不要な要素を1つずつ切り捨てる必要がある」** ということを説明しています。

---

## 3. 図解：なぜ 1 文字ズレるのか？

例えば、`["A", "B", "C"]` という 3 トークンの文章をモデルに入力する場合を考えます。

```text
  【 入力データ 】          位置 0: "A"            位置 1: "B"            位置 2: "C"
                            │                      │                      │
                            ▼                      ▼                      ▼
  【 モデル出力(ロジット)】 [ "B" の予測スコア ]   [ "C" の予測スコア ]   [ "???" の予測スコア ]
                            (位置 0 の出力)        (位置 1 の出力)        (位置 2 の出力)
                                                                                  │
                                                                                  ▼ (正解が存在しない!)
                                                                                  ★ 最後のロジットは捨てる
```

### 1 つずつ端っこを捨てる理由

1. **位置 0 の出力 ("B"の予測)** ──> 正解は **位置 1 のラベル "B"**
2. **位置 1 の出力 ("C"の予測)** ──> 正解は **位置 2 のラベル "C"**
3. **位置 2 の出力 ("???"の予測)** ──> これに対応する位置 3 の正解ラベルはデータ内に存在しない！ ──> **【最後のロジット】を捨てる (`output.logits[:, :-1, :]`)**
4. **位置 0 のラベル ("A")** ──> "A" の手前には単語がないため、"A" を予測したロジットは存在しない！ ──> **【最初のラベル】を捨てる (`labels[:, 1:]`)**

---

## 4. Python コードとの 1 対 1 対応関係

オライリー本の 139 ページのコードで行っているスライシングは、この両端カットの操作そのままです。

```python
log_probs = log_probs_from_logits(
    output.logits[:, :-1, :],  # ★ 最後のロジットを取り除く ( :-1 )
    labels[:, 1:]              # ★ 最初のラベルを取り除く ( 1: )
)
```

| 変数スライス | 取り出す範囲 | 意味 |
| :--- | :--- | :--- |
| **`output.logits[:, :-1, :]`** | 位置 0 〜 位置 1 | 末尾を削り、**「次の単語を予測した出力」** だけを残す |
| **`labels[:, 1:]`** | 位置 1 〜 位置 2 | 先頭を削り、**「実際に次に現れた正解単語」** だけを残す |

---

## 5. 「入力系列の対数確率は無視します」の意味

プロンプトとして最初に入力した文章（例: `"In a shocking finding,"`）は、人間が入力した条件であり、AI が自力で生成した文章ではありません。

AI が生成した「続きの文章」の出来栄え（評価スコア）だけを純粋に計算したいため、プロンプトの長さ分（`input_len`）は `log_probs[:, input_len:]` のように計算から除外しています。
