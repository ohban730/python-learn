# PyTorch `nn.Linear` (全結合層 / 線形層) の詳細ガイドと仕組み

ご質問の「`nn.Linear(入力次元数, 出力次元数)` と書けば内部で自動的にそのように変換するという解釈で合っているか？」という点について、**100% 正解** です。

`nn.Linear` の定義、計算式、および Transformer / LLM における最も重要な性質について改めて整理して解説します。

---

## 1. `nn.Linear(in_features, out_features)` の基本動作

### 結論：指定した通りに自動で次元を変換してくれます
`nn.Linear(入力次元数, 出力次元数)` と宣言しておくと、データを流し込んだ際に**最後の次元の要素数を自動的に指定した出力次元数へ変換（拡大・縮小・射影）** してくれます。

```python
import torch.nn as nn

# 「768次元 のベクトル」を 「3072次元 のベクトル」に拡大型変換する全結合層
linear_layer = nn.Linear(768, 3072)
```

---

## 2. 内部で行われている計算とパラメータ

`nn.Linear` の内部では、高校数学で習う **一次関数（$y = ax + b$ の行列版）** が計算されています。

$$y = x \cdot W^T + b$$

* **重み $W$ (`weight`)**: `Shape [out_features, in_features]`
  * 入力と出力を繋ぐ掛け算の係数（学習によって最適な値に更新される）。
* **バイアス $b$ (`bias`)**: `Shape [out_features]`
  * 足し算するオフセット値（偏り）。

PyTorch は `nn.Linear(in, out)` を作成した瞬間に、これら $W$ と $b$ のテンソルを内部に自動的に作成し、ランダムな初期値でセットして保持してくれます。

---

## 3. ★ LLM で極めて重要な性質：「一番最後の次元だけに作用する」

書籍の75ページにも書かれている `nn.Linear` の最も強力で重要な性質は、**「手前の次元（バッチ数や系列長など）の形は一切崩さず、一番最後の次元だけにピンポイントで作用する」** という点です。

### ① 2次元データの場合 (通常のテーブルデータなど)
* **入力**: `[batch_size, 768]`
* **出力**: `[batch_size, 3072]`

### ② 3次元データの場合 (Transformer / LLM の文章データ)
* **入力**: `[batch_size, seq_len, 768]`  （例: 2文章 × 5単語 × 768次元）
* **出力**: `[batch_size, seq_len, 3072]` （例: 2文章 × 5単語 × 3072次元）

```text
 ［ 入力 3次元テンソル ］
   ・バッチ数 (batch_size) :  2   ── (そのまま維持)
   ・単語数   (seq_len)    :  5   ── (そのまま維持)
   ・ベクトル (hidden_dim) : 768  ──★ ここだけが 3072 次元へ自動変換される！
```

### なぜこれが素晴らしいのか？ (位置単位 / Position-wise)
文章中の各単語（トークン）が持つベクトルに対して、**単語の位置関係を崩すことなく、1文字1文字のベクトル表現を独立して並列に次元変換** できるためです。

書籍で **「位置単位順伝播層 (position-wise feed-forward layer)」** と呼ばれているのは、この性質を利用して各トークンごとに独立して全結合層を適用しているからです。

---

## 4. まとめ

1. **解釈の正しさ**: `nn.Linear(入力次元, 出力次元)` と書くだけで、自動的にその次元へ変換してくれます（認識通りで完璧です）。
2. **内部の動き**: 重み $W$ とバイアス $b$ を使った線形計算 ($y = x W^T + b$) を自動で実行しています。
3. **次元の性質**: 手前の次元（バッチ数や単語数）は一切壊さず、**一番最後の次元だけをピンポイントで書き換える** ため、LLMの各トークン処理に最適です。
