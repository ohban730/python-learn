## 💡 1. Retriever-Reader アーキテクチャとは？

一言で言うと、**「数万件の巨大な文書群から一瞬で正確な答えを見つけ出すための 2 段階のチームプレイ構造」** です。

精密な読解モデル（Reader）は優秀ですが読むスピードが遅いため、数万件の文書すべてを読ませると応答に数分〜数十分かかってしまいます。そこで、足の速い検索担当（Retriever）がまず数件に絞り込みます。

```text
 ［ 膨大な文書 (数万件のレビューやPDF) ］
           │
           ▼ 【 1. Retriever (検索モジュール / 足の速いスカウト役) 】
 ［ 関連しそうな数件 (例: 3件) だけを爆速で絞り込む ］
           │
           ▼ 【 2. Reader (読解モジュール / 頭のいい分析官) 】
 ［ 絞り込まれた3件の文章をじっくり読んでピンポイントで答えを抽出 ］
           │
           ▼
 ［ 最終回答 ］: "1903年" または "バッテリーは持ちが悪い"
```

## 🔍 2. 「疎 (Sparse) 検索」と「密 (Dense) 検索」の概念とイメージ

Retriever（検索担当）の検索方法には、大きく分けて **「疎 (Sparse)」** と **「密 (Dense)」** の 2 つのアプローチがあります。

```text
 ■ 1. 疎 (Sparse) 検索 ──「辞書・キーワード検索」 (文字の完全一致)
    ・ベクトルイメージ : [ 0, 0, 0, 0, 1, 0, 0, 0, ... ]  (5万次元中、ほとんどが 0 ＝ スカスカ)
    ・特徴 : 「同じ単語が含まれているか？」で探す。型番や固有名詞に強い。

 ■ 2. 密 (Dense) 検索  ──「意味・ニュアンス検索」 (文脈・意味の一致)
    ・ベクトルイメージ : [ 0.24, -0.81, 0.15, 0.92, ... ] (768次元すべてに数値がぎっしり)
    ・特徴 : AIが文章の「意味」を理解して探す。言い換えや同義語に強い。
```

## 📊 3. 疎 (Sparse) vs 密 (Dense) の詳細比較表

| 比較項目 | 疎 (Sparse) 検索 | 密 (Dense) 検索 |
| :--- | :--- | :--- |
| **名前の由来** | 語彙数(約5万)のベクトルの要素のほとんどが `0`（**スカスカ＝疎**）だから | Transformerの隠れ状態(768次元)すべてに数値が詰まっている（**ぎっしり＝密**）だから |
| **代表的な手法** | **BM25**, TF-IDF, 単純なキーワード検索 | **DPR** (Dense Passage Retrieval), 埋め込み (Embedding) ベクトル検索 |
| **検索のアプローチ**| **単語・文字の完全一致**で探す | **文脈や意味の類似度（内積・コサイン類似度）**で探す |
| **得意なケース** | 型番（例: `"iPhone15"`）、人名、商品コードなどの明確な検索 | 「電池の持ちが悪い」と「バッテリーがすぐ切れる」のような**表現の言い換え検索** |
| **苦手なケース** | 表記揺れ（「スマホ」と「スマートフォン」）や同義語の対応 | マニアックな型番や数字のピンポイント検索 |

## 📝 まとめ

* **Retriever-Reader**: 「足の速い検索役（Retriever）」が候補を数件に絞り込み、「頭のいい読解役（Reader）」が正確な答えを抜き出す2段階システム。
* **疎 (Sparse)**: 単語の文字一致で探す従来のキーワード検索（型番などに強い）。
* **密 (Dense)**: AIが文章の意味を理解して似たニュアンスを探すモダンなベクトル検索（言い換えに強い）。
