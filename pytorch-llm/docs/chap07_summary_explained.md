## 🔺 2. 【最重要】図7-14「ニーズの階層ピラミッド」の教訓

まとめの中で最も重要なのが、219 ページの **「ニーズの階層（ピラミッド図）」** の話です。

```text
         ▲
        /  \       【レベル 3: 生成】 T5, RAG, GPT-3
       /    \       ・難易度最高。ハルシネーション（嘘）の対応が大変。
      /──────\
     /   抽出  \    【レベル 2: 抽出】 ドメイン適応, Zero-shot NER
    /          \    ・本文から答えをピンポイント切り抜き。嘘をつかない。
   /────────────\
  /     検索     \   【レベル 1: 検索】 TF-IDF, BM25, DPR
 /                \  ・すべての基本。関連する文書を正しく探してくる機能。
 -------------------
```

### 💡 筆者からの実務のアドバイス
> **「システムを作る時、いきなり一番上の流行り（ChatGPTやRAGなどの生成モデル）から作ろうとするな！」**

1. **まずはレベル 1（検索）**: ユーザーの質問に対して、正しく関連する文書を持ってこられる検索エンジン（BM25やDPR）をしっかり作る。
2. **次にレベル 2（抽出）**: 検索された文書から「答えのフレーズだけを正確に抜き出すモデル（Reader）」を作る。
3. **最後にレベル 3（生成）**: どうしても対話文章を作りたい場合のみ、最後に RAG や GPT などの生成モデルを検討する。

いきなり生成型（RAG）に行くと、AIの嘘（ハルシネーション）の修正やトラブル対応でドツボにはまるため、**ピラミッドの下から段階的に作るのが実務の成功法則**だと述べています。

## 💡 3. 読解モデル（Reader）の面白い応用例

まとめの文章で紹介されている **Grid Dynamics 社の事例** も重要です。

* **普通の使い方**: ユーザーが「このカメラ防水？」と聞いたら、AIが「30m防水です」と答える。
* **裏技の使い方**: 人間が質問するのではなく、AIに「自社製品の全レビュー」を読み込ませて、**「長所」と「短所」のフレーズを自動で一括抽出し、商品比較表を自動生成させる**。

 Reader（抽出モデル）はチャットボットだけでなく、**大量の文章から欲しい情報だけを抜き出すデータ分析ツール** としても強力です。

## 🔮 4. 質問応答（QA）の未来

最後に、今後の発展形として以下の3つが紹介されています：

1. **マルチモーダル QA**: テキストだけでなく、「この絵画はいつ描かれた？」「この表の合計は？」のように**画像や表（テーブル）も理解して答える**。
2. **知識グラフ QA**: 「人物 A と 企業 B の関係」のようなグラフ構造のデータベースから答えを探す。
3. **自動質問生成 (QG)**: AIが本文を読んで**自動で質問文を自作**し、学習用データを自動生成する。
